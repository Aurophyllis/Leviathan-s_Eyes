## 研究问题与预期边界

参考源码固定在 dsh-see-now 提交 `59c4d1a1b4bab0f6efec896f8bed578c352aca23`。64×36 HSV 网格差、切点尖峰、运动累积、超时兜底和有序拼图均属于上游工作。本组拟验证固定预算下的候选分配，以及用拼图定位后按时间回取清晰单帧的效果。复用源码时记录文件和改动，并随分发保留上游 LICENSE、NOTICE。[变化评分](https://github.com/SAOS-3624/dsh-see-now/blob/59c4d1a1b4bab0f6efec896f8bed578c352aca23/src/cuts.js) · [选帧流水线](https://github.com/SAOS-3624/dsh-see-now/blob/59c4d1a1b4bab0f6efec896f8bed578c352aca23/src/pipeline.js) · [拼图实现](https://github.com/SAOS-3624/dsh-see-now/blob/59c4d1a1b4bab0f6efec896f8bed578c352aca23/src/sheet.js)

硬切后的新画面、长镜头中的持续运动适合生成候选。摄像机抖动也会产生高变化分，而静止画面角落的小字可能决定答案。把变化分用作候选信号，并给平静时段预留预算。后续在相同相关性打分次数 B 和问答输入帧数 k 下，验证这个候选层与 AKS、FOCUS 结合后的收益。K-frames 的片段思路用于解释跨镜头证据及预算分配。

## 两人共用的接口约定 v0.1

Windows 用户在窗口中打开本地视频，获得当前会话的 `video_id`。软件在本机回环地址提供下列 HTTP 接口。只处理已打开的视频。连接器负责把 HTTP 图像响应转换成目标 Agent 支持的图像内容块。第一阶段采用 Python 桌面原型和轻量本地 HTTP 服务，插件/MCP 可以在此接口上独立开发。

| 操作 | 请求和返回 |
|---|---|
| 查询当前视频 | `GET /v1/videos/current` 返回 `video_id, duration_ms, width, height`。未打开视频返回 404。 |
| 请求一组帧 | `POST /v1/videos/{id}/observations` 接受下方 JSON。返回 `observation_id, video_id, method, frames, sheet_url`。每个 frame 含 `frame_id, t_ms, reason, image_url`。 |
| 看总览、追看细节 | 对 `sheet_url` 或 `image_url` 发 GET，得到带正确 MIME 的 PNG/JPEG 字节。URL 相对本机服务根路径。拼图格号从 1 开始，与 frames 的顺序一致。 |
| 区间复查 | 缩短起止时间重发 POST；取回该区间的新观察结果。未知 ID 返回 404，非法预算或区间返回 422 和可读错误。 |

```json
{"start_ms":0,"end_ms":10000,"k":4,"method":"change_guarded","query":""}
```

时间使用视频起点后的毫秒和左闭右开区间，按实际展示时间戳排序。第一阶段支持 `uniform`、`change_guarded` 两个软件方法。两者均独立于 query，字段留给后续语义选帧。区间内有足够候选时返回恰好 k 个不同时间戳，候选不足时返回实际数量并附 `shortfall`。软件、连接器和离线评测共用这套时间与排序约定。

## 评测口径

- 每个证据区间被至少一个选中时间戳命中即算覆盖。每题记录已覆盖区间数 / 必需区间数，同时统计全部必需区间均命中的题目比例。多段证据属于同一事件时先按题目标注定义固定分组。
- 让 Luo 固定模型、问题、帧大小和字幕设置，返回每题答案与是否正确。另测选帧耗时、解码耗时、总候选数和返回帧数。小样本按题给出增益、持平和退化例数。
- 阶段末若覆盖改善且静止细节题保留，进入语义打分对照；若主要收益为减少冗余，则用于软件总览；若抖动题或细节题明显退化，保留均匀回退并说明失败机制。后续取 Video-MME 与 KFS-Bench 标注交集扩大验证。研究结论写入报告实验章，指标以真实日志为依据。
